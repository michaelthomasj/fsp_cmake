Part 0 — The Cortex-M machine

A conventional primer. Everything later is built from the vocabulary established here, so it is worth reading even where it looks familiar. Addresses and numbers are from the real parts, not placeholders.

0.1 The core and the profile

Arm defines architectures and designs cores that implement them; vendors such as Renesas license a core and add memory and peripherals.

  • Armv8-M The M-profile is Arm's microcontroller architecture. Armv8-M comes in a Baseline (small, e.g. Cortex-M23) and a Mainline (full, e.g. Cortex-M33) variant. Armv8.1-M is a later revision of Mainline (Cortex-M55, Cortex-M85).
  • Armv8-M The Security Extension (marketed as TrustZone for Armv8-M) is optional in the architecture. Both parts in this course implement it.
  • RA The RA6M5 is a Cortex-M33 (__CM33_REV 0x0004, R7FA6M5BH.h:39). The RA8M2 has two cores: CPU0 is a Cortex-M85 (R7KA8M2JF_core0.h:39) and CPU1 a Cortex-M33 (R7KA8M2JF_core1.h:39). This port runs TF-M on CPU0.
  • RA Both device headers declare __MPU_PRESENT 1, __FPU_PRESENT 1 and __NVIC_PRIO_BITS 4 (lines 40–44). They differ on __SAUREGION_PRESENT: 0 on RA6M5, 1 on RA8M2. That one bit is the subject of a whole section of Part 2.

0.2 The register file

Armv8-M The core has sixteen 32-bit general-purpose registers and a small set of special registers reached only through MRS/MSR instructions.

  • R13, the stack pointer, is not one register. In Thread mode it is either the Main (MSP) or the Process stack pointer (PSP), chosen by CONTROL.SPSEL; in Handler mode it is always MSP. Operating systems give each task its own PSP and keep MSP for exceptions.
  • R14, the link register, holds a return address after BL. On exception entry it holds a special value, EXC_RETURN, that tells the core how to return. Decoding it is a core skill; see Part 1.
  • xPSR combines flags (APSR), the number of the exception being handled (IPSR; 0 in Thread mode) and execution state (EPSR, including the Thumb bit, which must always be 1).
  • MSPLIM and PSPLIM are new in Armv8-M. If SP is moved below the limit, the core raises a UsageFault (STKOF) instead of silently overwriting whatever lies below the stack.
The secure image sets both limits first thing in Reset_Handler (§0.5); Part 1 §1.3 shows TF-M swapping them per thread.

0.3 The stack and AAPCS basics

Armv8-M The stack is full-descending: SP points at the last item pushed, and a push decrements SP first. PUSH {r4, lr} stores two words and leaves SP 8 bytes lower.

The AAPCS (Procedure Call Standard for the Arm Architecture) is the contract between a caller and a callee. Compilers obey it; hand-written assembly must.

RegisterAAPCS roleWho preserves it
R0–R3First four arguments; R0 (and R1) carry the resultCaller, if it still needs them
R4–R11Local variablesCallee must restore them
R12Intra-procedure scratch (IP)Caller
SPMust be 8-byte aligned at every public function boundaryCallee
LRReturn addressCallee (pushes it if it calls anything)

Why it matters here. The hardware saves the caller-saved set (R0–R3, R12, LR, plus PC and xPSR) when an exception is taken. Because the callee-saved set is preserved by any AAPCS-compliant function, an ordinary C function can be an interrupt handler with no assembly wrapper. A context switch moves to a different stack and must save R4–R11 itself (TF-M's PendSV, Part 1 §1.7).

0.4 The Armv8-M memory map, with RA addresses

Armv8-M The 4 GB address space is divided into fixed architectural regions. The architecture assigns each a default memory type (normal or device) and whether code may execute from it. A vendor decides what to place inside each region.

  • Armv8-M The Peripheral region is device memory: accesses are not merged, reordered or cached, and instruction fetch from it is forbidden.
  • RA Option-setting memory (OFS), at 0x0100A100 on RA6M5 and 0x02C9F040 on RA8M2, configures the part at reset; some bits are one-time, and a wrong write can brick the part. Linker rule: DESIGN.md §8.4; checks before flashing: GETTING_STARTED.md §6.
Which half of each region is secure is not visible in this map at all. It is decided by the SAU and IDAU, and on RA by boundary registers programmed once per board. See Part 2 §2.2.

0.5 The vector table and reset

Armv8-M The vector table is an array of 32-bit words in memory. Word 0 is the initial value of MSP; word 1 is the address of the reset handler; word n (for n ≥ 2) is the address of the handler for exception number n. The core finds the table through VTOR (Vector Table Offset Register, 0xE000ED08).

On reset the core:

  1. loads MSP from [VTOR + 0];
  2. loads PC from [VTOR + 4] (bit 0 must be 1, marking Thumb state);
  3. starts executing in Thread mode, privileged, using MSP, in Secure state if the Security Extension is present.

The RA6M5 secure image's table, abridged:

#define RA6M5_VECTOR_TABLE_ENTRIES  (112)

    Reset_Handler,                            /*     Reset Handler */
    NMI_Handler,                              /* -14 NMI Handler */
    HardFault_Handler,                        /* -13 Hard Fault Handler */
    ...

    ...
    PendSV_Handler,                           /*  -2 PendSV Handler */
    SysTick_Handler,                          /*  -1 SysTick Handler */

    /* ICU slots 0..95 - event-linked, see the note above the declarations */

    ...

ra6m5/startup_ra6m5.c:115-155

  • RA 112 entries = 16 architectural exceptions + 96 interrupt slots. The 96 is the RA6M5's ICU slot count (BSP_VECTOR_TABLE_MAX_ENTRIES (112U), quoted at startup_ra6m5.c:105-107).
  • This port Every interrupt slot defaults to Default_Handler, a while(1). The one interrupt the port services, the AGT0 timer, is overridden by a later designated initializer. In C, when an index is initialized twice, the last initializer wins, so the order of these two lines is load-bearing (comment at startup_ra6m5.c:139-153).

The reset handler itself:

__NO_RETURN void Reset_Handler(void)
{
#if defined (__ARM_FEATURE_CMSE) && (__ARM_FEATURE_CMSE == 3U)
    __disable_irq();
#endif
    __set_PSP((uint32_t)(&__INITIAL_SP));
    __set_MSPLIM((uint32_t)(&__STACK_LIMIT));
    __set_PSPLIM((uint32_t)(&__STACK_LIMIT));
#if defined (__ARM_FEATURE_CMSE) && (__ARM_FEATURE_CMSE == 3U)
    __TZ_set_STACKSEAL_S((uint32_t *)(&__STACK_SEAL));
#endif
    SystemInit();                             /* CMSIS System Initialization */
    __PROGRAM_START();                        /* Enter PreMain (C library entry point) */
}

ra6m5/startup_ra6m5.c:164-181

    • SystemInit() (FSP) sets clocks, TrustZone attribution and interrupt routing; __PROGRAM_START() then copies .data and zeroes .bss.
    • This port BL2 boots from 0x00000000 and jumps to the secure image, whose SystemInit() rewrites VTOR.
TF-M's reset runs SystemInit() before .bss is zeroed, so FSP state stored in .bss is lost. The remedy is in Part 4 §4.4.
Why does the timer's slot point at a TF-M handler and not at FSP's agt_int_isr? Because FSP's ISR would call the driver callback directly and bypass the secure partition manager. See Part 2 §2.6.

0.6 Exception numbers and priorities

Armv8-M An exception is any event that makes the core stop what it is doing and run a handler: an interrupt from a peripheral, a fault, or an explicit request from software. Each has a number, which is its index into the vector table.

No.CMSIS IRQnExceptionPriorityRaised by

CMSIS numbers IRQn as exception number − 16, so AGT0 (ICU slot 0) is IRQn 0, exception 16, vector index [16 + 0].

Priority

  • Armv8-M Lower number = more urgent. A pending exception preempts the running one only if its priority number is strictly lower.
  • Armv8-M Priority fields are 8 bits wide, but an implementation keeps only the top __NVIC_PRIO_BITS bits. RA RA6M5 and RA8M2 keep 4, so there are 16 levels and the field values that matter are 0x00, 0x10, … 0xF0. CMSIS's NVIC_SetPriority(irq, 4) writes 0x40.
  • Armv8-M Reset, NMI and HardFault have fixed negative priorities and always win.

Why PendSV is 0x70, "just below 0x80", only makes sense once you know that TrustZone can confine all non-secure priorities to 0x80–0xFF. See Part 2 §2.5.

Masking

  • PRIMASK = 1 (cpsid i, CMSIS __disable_irq()) masks every exception with configurable priority — including SVCall.
  • BASEPRI = x masks exceptions whose priority number is ≥ x.
  • FAULTMASK masks everything except NMI.
An SVC issued while PRIMASK is set cannot be taken and escalates to HardFault (Part 1 §1.8).

0.7 Interrupt latency and tail-chaining

Armv8-M On exception entry the hardware, without any instruction from software:

  1. pushes eight words — R0–R3, R12, LR, the return address and xPSR — onto the current stack;
  2. in parallel, fetches the handler address from the vector table;
  3. writes EXC_RETURN into LR, switches to Handler mode and MSP, and branches.

The handler is therefore an ordinary C function. On return (BX LR with an EXC_RETURN value) the hardware unstacks.

  • Tail-chaining. If another exception is pending when a handler returns, the core skips the unstack-then-restack and goes straight to the next handler.
  • Late arrival. If a more urgent exception arrives while stacking is still in progress, the core redirects to the more urgent handler using the same stack frame.
  • Latency. Arm quotes 12 cycles to the first handler instruction, and 6 for a tail-chain, on zero-wait-state Cortex-M3/M4-class cores. Flash wait states, lazy FP stacking and TrustZone state add to it. This port has not measured it.
The hardware pushes more than eight words when a secure context is interrupted by a non-secure interrupt. See Part 1 §1.5.

0.8 The NVIC — and RA's ICU in front of it

Armv8-M The Nested Vectored Interrupt Controller is part of the core, in the System Control Space. For each external interrupt it holds an enable, a pending and an active bit, a priority, and (with the Security Extension) a target security state.

Register arrayAddressPurposeCMSIS
ISER0xE000E100set-enable (write 1)NVIC_EnableIRQ
ICER0xE000E180clear-enableNVIC_DisableIRQ
ISPR0xE000E200set-pendingNVIC_SetPendingIRQ
ICPR0xE000E280clear-pendingNVIC_ClearPendingIRQ
IABR0xE000E300active (read-only)NVIC_GetActive
ITNS0xE000E380target non-secure (Secure-only)NVIC_SetTargetState
IPR0xE000E400priority, one byte per interruptNVIC_SetPriority

The base, NVIC_BASE = SCS_BASE + 0x0100 = 0xE000E100, is from core_cm33.h:2045; the offsets within it are architectural.

RA puts an Interrupt Controller Unit in front

RA RA peripherals do not have fixed NVIC lines. Each peripheral raises an event; the ICU routes up to 96 chosen events to NVIC lines 0–95 through IELSR[n] (ICU Event Link Setting Register), at 0x40006300 + 4n (R_ICU_BASE 0x40006000, IELSR[96] at offset 0x300, R7FA6M5BH.h:9372).

  • RA IELSR is programmed once at boot by FSP's bsp_irq_cfg() from a table the e2 configurator generates, g_interrupt_event_link_select[] in ra_gen/vector_data.c. Slots are assigned densely in the order interrupts were added to the project, so adding one earlier interrupt renumbers the rest (ra6m5/tfm_peripherals_def.h:51-58).
  • RA The ICU latch IELSR.IR holds the request until software clears it. Without the clear "the interrupt fires exactly once" (D069).
Which code may clear each latch is a privilege question: Part 3 §3.6.

0.9 SysTick

Armv8-M SysTick is a 24-bit down-counter in the System Control Space, intended as an operating-system tick.

RegisterAddressPurpose
SYST_CSR0xE000E010enable, interrupt enable, clock source, COUNTFLAG
SYST_RVR0xE000E014reload value (24 bits)
SYST_CVR0xE000E018current value; any write clears it
SYST_CALIB0xE000E01Ccalibration
  • When the counter reaches zero it reloads from RVR and, if enabled, raises exception 15.
  • Armv8-M With the Security Extension a second SysTick may exist for the Non-secure state; Secure code reaches it at 0xE002E010 (SysTick_BASE_NS).
  • TF-M The secure image does not run a tick. Its scheduler is event-driven (PendSV, Part 1). The non-secure FreeRTOS application is the natural SysTick user.

0.10 The Private Peripheral Bus

Armv8-M The PPB (0xE0000000–0xE00FFFFF) holds the core's own control registers rather than vendor peripherals. Its most important part is the System Control Space (SCS) at 0xE000E000:

BlockBaseContains
SysTick0xE000E010§0.9
NVIC0xE000E100§0.8
SCB0xE000ED00ICSR (ED04), VTOR (ED08), AIRCR (ED0C), SHCSR (ED24), CFSR (ED28), HFSR (ED2C), MMFAR (ED34), BFAR (ED38)
MPU0xE000ED90TYPE, CTRL, RNR, RBAR, RLAR, MAIR0/1 (Part 1)
SAU0xE000EDD0CTRL, TYPE, RNR, RBAR, RLAR; SFSR at 0xE000EDE4 (Part 2)
SCS, non-secure alias0xE002E000the non-secure copies of banked registers, visible to Secure code only

Bases: core_cm33.h:2038-2087. Register offsets within the SCB are architectural.

Armv8-M The rule that matters most later: the PPB is accessible only to privileged software. An unprivileged access to it takes a BusFault. This is a property of the architecture, not a setting: the MPU (Part 1) does not apply to PPB addresses, so no MPU region can grant unprivileged code access to them. The exceptions are a few registers with their own unprivileged-access controls — STIR (0xE000EF00) when CCR.USERSETMPEND = 1, and the ITM stimulus ports under ITM_TPR. None of the NVIC or SCB registers this course discusses is among them.

This rule is why an unprivileged partition cannot call an interrupt-driven R_xxx_Open() (Part 3 §3.9) or clear an NVIC pending bit (§3.6), and why the fault in Part 1 §1.9 is a BusFault on ICSR.

Check yourself

  1. In startup_ra6m5.c, what happens if the line [16 + 0] = TFM_TIMER0_IRQ_Handler is moved above the range initializer [16 ... 111] = Default_Handler?
    AnswerFor a repeated index the last initializer wins, so slot 16 would become Default_Handler and the timer interrupt would hang in its while(1) instead of reaching the SPM.
  2. NVIC_SetPriority(TFM_TIMER0_IRQ, 4) runs on an RA6M5. What byte lands in the IPR register, and is the timer more or less urgent than PendSV under TF-M?
    Answer4 bits are implemented, so 4 is shifted into the top nibble: 0x40. PendSV is at 0x70; lower number is more urgent, so the timer is more urgent and can preempt PendSV.
  3. A C function is used directly as an interrupt handler. Why does it not need to save R4–R11, but a context switch does?
    AnswerThe hardware saves the caller-saved set (R0–R3, R12, LR, PC, xPSR); the AAPCS obliges any function to preserve R4–R11 itself. A context switch resumes a different thread whose R4–R11 values are not the current ones, so it must save and restore them explicitly.
  4. Why can no configuration of the MPU allow unprivileged code to write 0xE000E280?
    AnswerIt is ICPR in the NVIC, part of the PPB. The PPB is privileged-only by architecture and the MPU does not apply to it.
  5. On RA, which three places can hold a pending AGT0 interrupt request?
    AnswerThe AGT's own status flag (AGTCR.TUNDF), the ICU latch IELSR[0].IR, and the NVIC pending bit for IRQ 0.
